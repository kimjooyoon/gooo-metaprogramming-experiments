# Local 100-candidate run — 2026-09-29

## Setup

- Apple M4, 10 CPU cores; Laya served on CPU with two Torch threads.
- Laya checkpoint revision: `55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851`.
- Ten distinct Korean task descriptions, ten route choices, 25 integer inputs
  per intent; 100 generated candidate functions in one 138,705-byte Go file.
- Reports contain complete per-task probabilities and per-candidate scores.

## Results

| Measure | Laya top-1 | Seeded probability sample | Deterministic fallback |
| --- | ---: | ---: | ---: |
| Input/output matches | 250/250 | 244/250 | 250/250 |
| Reachable rule clauses | 33/33 | 32/33 | 33/33 |
| Candidates compiled | 100/100 | 100/100 | 100/100 |
| Candidate source replays matched | 100/100 | 100/100 | 100/100 |
| Expected construct coverage | 100% | 100% | 100% |

Top-1 matched the simple deterministic fallback; it did not improve completeness
on this small corpus. A seeded probability draw selected an intentionally
partial route once, omitting 6 of 250 outputs and one reachable rule clause.
That illustrates why probabilistic code composition should emit a candidate
for evaluation and retain a hard completeness gate before selecting it.

The current route set has an oracle ceiling of 100% because nine routes are
complete for this fixture domain. Six `partial_assignment` candidate cases
showed finite-domain completeness of 52%, 92%, 84%, 76%, 48%, and 96%.

## Cost

For the final sequential Laya pass (10 route decisions): mean response time was
119.6 ms per decision and p95 was 151.0 ms. A separate pass of the same batch
measured 1.45 CPU seconds over 1.77 wall seconds for the Laya process: 82% of
one core on average, or 8.2% of this 10-core host. RSS was 603 MiB before and
after. The deterministic fallback averaged 4.9 ms per `gooo decide` call (p95
5.4 ms) and used no model process.

This request offers ten construction routes and a longer task description,
compared with the earlier two-option local probe (p50 61.6 ms). The two timings
are not controlled against identical prompt size. No causal speed claim is
made.

## Interpretation

The promising boundary is planner/IR to bounded route selection to a
deterministic emitter. Laya can select control-flow shape, but it does not
generate code or establish semantic correctness. The current Gooo CLI still
generates declaration projections; the experimental helper bodies are emitted
by the lab's separate Go renderer. Before integrating this into the language,
the corpus should add larger domains, string and record inputs, missing data,
multi-output behavior, and independent property-based oracles. Laya
probabilities need Gooo-specific calibration before production use.

The model card describes Laya as a decision model rather than a text generator
and reports weaker-than-majority results for the base checkpoints on its
typed-decision benchmark: [Laya model card](https://huggingface.co/convaiinnovations/laya).
